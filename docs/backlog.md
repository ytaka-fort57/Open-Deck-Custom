## 優先度: 高

### 1. プロファイル切り替え時のタブ復元が未検証

カラムごとの選択タブは `opd_custom_column_state` に `プロファイル番号:カラム位置` で保存している。
プロファイル切り替えはページをリロードせずカラムを作り直すため（[content.js:976](../content.js:976)）、
新しいプロファイル番号の保存と再生成がほぼ同時に走る。

切り替え直後に古い番号を読むと、別プロファイルのタブを復元したり、保存先を取り違える恐れがある。
P0 と P1 で別々のタブ構成を作り、切り替えて確認すること。

### 2. 本家のプロファイル自動復旧が壊れている（未修正）

`profile_store[last_load_profile]` が欠けている場合の復旧経路
（[content.js:156](../content.js:156)、[content.js:179](../content.js:179)）に不具合が2つある。

- `window.reload()` は存在しない API。他所では `location.reload()` を使用（[content.js:1532](../content.js:1532)）
- 復旧の `if` ブロックに `return` がなく、非同期の `set` コールバックを待たずに
  直後の `profile_store[last_load_profile].profile` を参照して例外になる

結果、復旧されずデッキが描画されないまま止まる。本家にも同じ不具合があるため、
修正後は本家への Pull Request も検討する。

### 3. カラムごとの「戻る」が別のカラムに効く

ブラウザーの戻る操作は、フレームをまたいだ joint session history を対象とするため、
「最後に遷移したカラム」が戻る。X の戻るボタンも内部で同じ経路を使う。
Backspace での戻るも同じ理由で単純には実装できない。

カラム単位の戻るを実現するには、カラムごとに URL の履歴を独自に持ち、
そのカラムだけを前の URL へ移動させる必要がある。

## 優先度: 中

### 4. カラムの並べ替え・追加・削除でタブの対応がずれる

保存が「左から何番目のタイムラインカラムか」という位置基準のため。
ずれてもタブを選び直せば直る。

## 既知の制約（対応しない）

- 「おすすめ」と「フォロー中」を別々のカラムに同時表示することはできない。
  X がこの2つに固有の URL を持たず、タブ選択をアカウント単位で共有しているため。
  リストは `/i/lists/<id>` の URL を持つため、Explore カラムとして開けば独立して復元できる。
